Askable Widget - With SRI (Subresource Integrity)

About SRI

This example demonstrates how to use Subresource Integrity (SRI) hashes to verify the widget script hasn't been tampered with.

Benefits:

  • ✅ Prevents script tampering
  • ✅ Protects against compromised CDNs
  • ✅ Detects man-in-the-middle attacks

⚠️ Important

Replace YOUR_SITE_ID and YOUR_SRI_HASH with actual values:

  1. Get your site ID from your Askable dashboard
  2. Fetch the SRI hash from: https://askable.gentic.in/versions/latest/sri-hashes.json
  3. Use the hash value from the askable-ws.js entry

How to Get SRI Hash

Method 1: Fetch from API

// JavaScript example
const response = await fetch('https://askable.gentic.in/versions/latest/sri-hashes.json');
const data = await response.json();
const hash = data['askable-ws.js'].hash;
console.log(hash); // sha384-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

Method 2: Direct URL

Visit: https://askable.gentic.in/versions/latest/sri-hashes.json

Look for the askable-ws.js entry and copy the hash value.

Method 3: Specific Version

For a specific version: https://askable.gentic.in/versions/v1.0.0/sri-hashes.json

Replace v1.0.0 with your desired version.

Example Script Tag

<script
  src="https://askable.gentic.in/versions/latest/askable-ws.js"
  integrity="sha384-YOUR_SRI_HASH_HERE"
  crossorigin="anonymous"
  data-site-id="YOUR_SITE_ID"
  data-widget-type="ws"
></script>

Note: Always include crossorigin="anonymous" when using SRI.
